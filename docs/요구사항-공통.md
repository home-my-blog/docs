# 공통 요구사항 (회의 전 초안)

> 2026-10-02 기준 초안입니다. 팀원 4명의 요구사항 문서(MyBlog, OwnLog, 끄적, Ylog)를 기능별로 비교해서, **모두가 함께 만들 최소 기능**만 뽑았습니다.
> 구현은 각자 하므로, 이 문서는 **기술과 서비스 이름을 정하지 않고** "무엇을 할 수 있어야 하는가"만 적습니다.
> 근거가 된 비교는 [요구사항-비교표.md](요구사항-비교표.md)에 있습니다.

## 이 문서 읽는 법

| 구분 | 뜻 |
|---|---|
| **공통 필수** | 4개 문서에 모두 있습니다. 모두가 만듭니다. |
| **공통 권장** | 일부 문서에만 있지만 팀이 합의하면 넣을 수 있습니다. **구현할지는 각자 선택합니다.** |
| **개인** | 한 문서에만 있거나 컨셉에 따라 다릅니다. 각자의 개인 요구사항 문서에 둡니다. |

- `회의 결과` 칸은 비워 두었습니다. 회의에서 **합의 / 개인으로 / 보류** 중 하나를 적습니다.
- **하나라도 동의하지 않으면 공통에 넣지 않고 개인 요구사항으로 둡니다.**
- `[합의 필요]` 표시는 문서마다 달라서 회의에서 정해야 하는 항목입니다. (7장 참고)

## 1. 용어 (이 문서에서의 약속)

문서마다 부르는 이름이 달라서, 공통 문서에서는 아래 말로 통일합니다.

| 공통 용어 | 뜻 | 각 문서에서의 이름 |
|---|---|---|
| 회원 | 가입한 사용자 | 모두 같음 |
| **공간** | 회원이 글을 담아 두는 곳 | 블로그 (MyBlog, OwnLog, Ylog) / 다이어리 (끄적) |
| 글 | 공간 안에 쓰는 게시물 | 글 / 끄적 |
| **분류** | 글을 나누는 단위 | 카테고리 (MyBlog, OwnLog, Ylog) / 다이어리 (끄적) |
| 공개 범위 | 글을 누가 볼 수 있는지 | 글 단위 (OwnLog, Ylog) / 다이어리 단위 (끄적) |

> 끄적에서는 다이어리가 **공간과 분류를 겸하는** 것으로 읽혔습니다. 이 해석이 맞는지 끄적 문서 작성자에게 확인이 필요합니다.

## 2. 공통 필수 기능

4개 문서에 모두 있는 기능입니다.

| ID | 기능 | 상세 | 문서별 차이 / 비고 | 회의 결과 |
|---|---|---|---|---|
| CF-01 | 회원 가입 | 이메일, 닉네임, 비밀번호로 가입한다. 모든 입력은 필수이고, 이메일은 이메일 형식이어야 한다. | OwnLog는 아이디도 입력한다. 끄적은 비밀번호 확인칸이 있다. | |
| CF-02 | 로그인 / 로그아웃 | 이메일과 비밀번호로 로그인하고, 로그아웃할 수 있다. | 인증 방식(세션, 토큰)은 기술이라 이 문서에서 정하지 않는다. | |
| CF-03 | 글 공간 | 회원은 글을 담는 **공간을 1개 이상** 가진다. 개수와 이름은 각자 정한다. | **[합의 필요 ①]** 우리는 미정, OwnLog는 1개, 끄적·Ylog는 여러 개 | |
| CF-04 | 공간 정보 설정 | 공간의 이름과 소개를 정하고 바꿀 수 있다. | 우리는 수정 화면이 아직 없다. | |
| CF-05 | 글 작성·수정·삭제 | 회원은 글을 쓰고, 고치고, 지울 수 있다. | 우리는 화면이 아직 없다. | |
| CF-06 | 글의 필수 항목 | **본문은 필수**다. 제목의 필수 여부는 각자 정한다. | 끄적은 제목이 선택이다. 우리 문서에는 필수 여부가 아직 적혀 있지 않다. | |
| CF-07 | 글의 분류 | 모든 글은 반드시 **하나의 분류**에 속한다. | | |
| CF-08 | 분류 관리 | 분류를 추가·수정·삭제하고 순서를 바꿀 수 있다. 삭제할 때 **안의 글을 어떻게 할지** 정해야 한다. | **[합의 필요 ③]** 삭제 규칙이 다르다: 우리는 "글이 있으면 삭제 불가", Ylog는 "분류 없음으로 이동", 끄적은 "이동 또는 함께 삭제". 구체 규칙은 각자 정한다. | |
| CF-09 | 글 상세 | 글 하나의 분류, 작성 시각, 본문(제목이 있으면 제목)을 볼 수 있다. | | |
| CF-10 | 글 목록 | 최신 글이 먼저 보인다. 한꺼번에 불러오지 않고 **나눠서** 보여 준다. | **[합의 필요 ⑤]** 방식이 다르다: 페이지 번호(우리, Ylog), 무한 스크롤(OwnLog), 더 보기(끄적). 방식은 각자 정한다. | |
| CF-11 | 글 검색 | 제목과 본문에서 키워드로 찾을 수 있다. | 범위가 다르다: 전체 공개 글(우리, OwnLog, Ylog) / 내 글(끄적). 범위는 각자 정한다. | |
| CF-12 | 작성자 권한 | 글은 **작성자 본인만** 수정·삭제할 수 있다. 로그인하지 않은 사람은 글을 쓸 수 없다. | | |
| CF-13 | 공개 범위 | 공개와 비공개를 구분할 수 있다. 비공개는 본인만 볼 수 있다. | **[합의 필요 ④]** 단위가 다르다: 글(OwnLog, Ylog) / 다이어리(끄적). 끄적은 1차에서 비공개만 있고, 우리는 아직 후순위다. 단위와 1차 범위는 각자 정한다. | |

## 3. 공통 권장 기능

일부 문서에만 있습니다. **구현할지는 각자 선택**하되, 구현한다면 아래 규칙을 따릅니다.

| ID | 기능 | 상세 | 있는 문서 | 회의 결과 |
|---|---|---|---|---|
| CF-14 | 이메일 중복 가입 불가 | 이미 가입된 이메일로는 다시 가입할 수 없다. | OwnLog, 끄적, Ylog (우리 문서에 추가 필요) | |
| CF-15 | 내 정보 관리 | 닉네임·소개 수정, 비밀번호 변경(현재 비밀번호 확인), 회원 탈퇴 | OwnLog, Ylog / 끄적은 메뉴만 있음 | |
| CF-16 | 로그인 유도 | 로그인이 필요한 기능을 로그인 없이 누르면 로그인 화면을 보여 준다. | 우리, 끄적, Ylog | |
| CF-17 | 방문자의 공개 글 읽기 | 로그인하지 않아도 공개된 글을 읽을 수 있다. | **[합의 필요 ⑥]** 우리, OwnLog, Ylog에는 있고, 끄적은 1차가 나만 보는 기록장이라 "나중에"이다. | |
| CF-18 | 댓글 | 로그인한 회원만 쓸 수 있다. 작성자 본인은 삭제할 수 있다. | OwnLog, Ylog, 우리(커뮤니티에만 있음) / 끄적은 나중에 | |
| CF-19 | 좋아요 | 회원이 글에 좋아요를 누르고 취소할 수 있다. | OwnLog, Ylog / 끄적은 "끄덕"으로 나중에 | |
| CF-20 | 태그 | 글에 태그를 붙이고, 태그로 글을 모아 볼 수 있다. | OwnLog, Ylog / 끄적은 미정 | |
| CF-21 | 신고 | 회원이 글을 사유와 함께 신고할 수 있다. 처리는 관리자 기능과 함께 2차로 둔다. | OwnLog, Ylog / 끄적은 나중에 | |
| CF-22 | 이미지 업로드 | 글에 이미지를 넣을 수 있다. | OwnLog, Ylog / 저장 방식에 따라 난이도가 크게 다르다. | |
| CF-23 | 관리자 기능은 2차 | 이번 범위에서는 관리자 기능을 만들지 않는다. | **4개 문서 모두 후순위** | |
| CF-24 | 외부 인증 제외 | 이메일 인증과 소셜 로그인은 이번 범위에서 만들지 않는다. | OwnLog, Ylog, 우리 | |

### 공통 비기능 (권장)

|---|---|---|---|
| NF-01 | 비밀번호는 원문 그대로 저장하지 않는다. (단방향 해시) | OwnLog, Ylog | |
| NF-02 | 글 수정·삭제 권한은 서버에서 검사한다. 화면에서만 막지 않는다. | OwnLog, Ylog | |
| NF-03 | 휴대폰 화면에서도 읽고 쓸 수 있다. (반응형) | OwnLog, 끄적, Ylog (우리 문서에는 아직 없음) | |

## 6. 이 문서에서 일부러 정하지 않은 것

- **서비스 이름**: MyBlog, OwnLog, 끄적, Ylog는 각자의 이름입니다.
- **기술 스택, DB, 인증 방식, 배포**: 각자 정합니다.
- **화면 모양과 디자인**: 각자의 시안을 따릅니다.
- **기능 ID 접두어**: 이 문서는 임시로 `CF-`(공통 기능)와 `NF-`(비기능)를 썼습니다. 팀이 정한 접두어가 있으면 바꿉니다.

## 7. 합의가 필요한 충돌

| 번호 | 충돌 | 제안 | 회의 결과 |
|---|---|---|---|
| ① | 공간이 1개 / 여러 개 / 다이어리 여러 권으로 다름 | 공통은 "1개 이상"으로 쓰고 개수는 각자 정한다. (CF-03) | |
| ② | 용어가 카테고리 / 다이어리 / 분류로 다름 | 공통 문서에서는 "분류"로 통일한다. (1장) | |
| ③ | 분류 삭제 시 안의 글 처리가 3가지 | 공통은 "처리 방법을 정해야 한다"까지만 쓴다. (CF-08) | |
| ④ | 공개 범위의 단위(글 / 다이어리)와 1차 범위가 다름 | 공통은 "공개·비공개를 구분한다"까지만 쓴다. (CF-13) | |
| ⑤ | 목록 방식이 페이지 / 무한 스크롤 / 더 보기로 다름 | 공통은 "나눠서 보여 준다"까지만 쓴다. (CF-10) | |
| ⑥ | 방문자의 공개 글 읽기: 끄적은 1차에 없음 | 공통 필수가 아니라 **공통 권장**으로 둔다. (CF-17) | |

## 8. 회의 후 할 일

1. 회의 결과 칸을 채워서 이 문서를 확정합니다. (합의된 기능만 남기고, 나머지는 개인으로 옮김)
2. 각자의 개인 요구사항 문서를 만듭니다. (이 문서의 5장을 출발점으로)
3. 확정된 공통 기능을 기준으로 각자 기술 스택, 아키텍처, ERD로 넘어갑니다.
