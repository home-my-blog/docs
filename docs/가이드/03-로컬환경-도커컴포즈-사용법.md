# 03. 로컬 환경: Docker Compose 사용법

> **한 줄 요약:** 서버를 만들 때 필요한 부품 3개(DB, Redis, 이미지 저장소)를 **명령 한 줄로 내 컴퓨터에 켜 주는** 방법입니다. 서버와 화면은 평소처럼 IntelliJ와 터미널에서 실행합니다.
> 상태: **가안**입니다. 실제 `docker-compose.yml`은 구현 단계에서 만듭니다. 이 문서의 Compose는 **개발용**이며, 배포는 [05-배포-준비.md](05-배포-준비.md)에서 따로 다룹니다.
> 관련 파일: [01-서버와-접속도구.md](01-서버와-접속도구.md), [02-도커-컴포즈-쿠버네티스.md](02-도커-컴포즈-쿠버네티스.md), [04-MinIO-현황과-선택.md](04-MinIO-현황과-선택.md)
> 읽는 순서는 [00-목차.md](00-목차.md)를 봅니다.

## 1. 왜 우리 프로젝트에 필요한가

| 부품 | 맡은 일 | 관련 요구사항 |
|---|---|---|
| **PostgreSQL** (DB) | 회원, 블로그, 글, 댓글 등 거의 모든 데이터 저장. **로그인 세션도 여기에 저장** | 세션 7일 유지(CF-02-10), 보안(NF-10~12) |
| **Redis** (임시 저장소) | 이메일 인증번호(10분 뒤 자동 삭제), 인증 완료 표시(30분), 조회수 중복 방지(30분), 방문자 하루 1번 표시, 실시간 인기 검색어 | 이메일 인증(CF-01-11, 14, 16, 17, 20), 통계(BM-06-3, 4) |
| **MinIO** (이미지 저장소) | 글에 올린 이미지 파일 저장 | 이미지 업로드(CF-22) |

요구사항은 [상세/01-인증-인가.md](../상세/01-인증-인가.md), [상세/05-소통-부가.md](../상세/05-소통-부가.md), [상세/06-블로그관리-통계.md](../상세/06-블로그관리-통계.md)에 있습니다.

세 개를 따로 설치하면 설치 방법이 제각각이고 버전 충돌이 날 수 있으며 지우기도 어렵습니다. Compose를 쓰면 **어느 컴퓨터에서든 똑같은 환경이 한 줄로 켜지고, 망가지면 지우고 다시 만들 수 있습니다.**

## 2. 켜지는 것과 안 켜지는 것

```
내 노트북
┌────────────────────────────────────────────────────────┐
│ Docker Compose가 켜는 것 (상자 3개)                      │
│   [ PostgreSQL :5432 ]  [ Redis :6379 ]  [ MinIO :9000 ] │
└────────────────────────────────────────────────────────┘
                 ▲                ▲               ▲
                 └────────── 서버가 접속 ──────────┘
IntelliJ에서 직접 실행: 서버(Spring Boot)
터미널에서 직접 실행:  화면(React, npm run dev)
```

서버와 화면을 상자에 넣지 않는 이유는, 코드를 고치고 바로 실행해서 확인하기 편하기 때문입니다.

## 3. 주문서 예시 (`docker-compose.yml`)

이해를 위한 예시입니다. 버전 숫자와 이미지 이름은 구현 때 다시 확인합니다.

```yaml
services:
  db:                                   # PostgreSQL
    image: postgres:16
    environment:
      POSTGRES_DB: myblog
      POSTGRES_USER: myblog
      POSTGRES_PASSWORD: ${DB_PASSWORD}      # 비밀번호는 .env 파일에서 읽는다
    ports: ["5432:5432"]                     # "내 컴퓨터 문 번호:상자 안 문 번호"
    volumes: [db-data:/var/lib/postgresql/data]   # 데이터는 냉장고(볼륨)에 보관
    healthcheck:                             # 켜졌는지 스스로 점검
      test: ["CMD-SHELL", "pg_isready -U myblog"]
      interval: 10s
      retries: 5

  redis:                                # Redis
    image: redis:7
    ports: ["6379:6379"]
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      retries: 5

  minio:                                # 이미지 저장소
    image: bitnamilegacy/minio:2025.7.23-debian-12-r5   # 예전 프로젝트(aiot3)에서 쓴 고정 버전
    environment:                         # 이 이미지 전용 설정 이름. 이미지가 바뀌면 달라진다
      MINIO_ROOT_USER: ${MINIO_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_PASSWORD}
      MINIO_DEFAULT_BUCKETS: myblog-images   # 이미지를 담을 폴더(버킷)를 처음부터 만든다
    ports: ["9000:9000", "9001:9001"]    # 9000 = 파일 주고받는 문, 9001 = 관리 화면
    volumes: [minio-data:(이미지가 정한 데이터 폴더)]   # 폴더 경로는 구현 때 확인

volumes:                                # 냉장고 목록
  db-data:
  minio-data:
```

`.env` 파일 (같은 폴더에 두고 **Git에 올리지 않음**):

```
DB_PASSWORD=개발용비밀번호
MINIO_USER=minioadmin
MINIO_PASSWORD=개발용비밀번호
```

- `.gitignore`에 `.env`를 넣고, 비밀번호 칸만 비운 `.env.example`을 대신 올립니다. 팀원은 이 파일을 복사해서 씁니다.
- MinIO 이미지가 지금도 받아지는지는 구현 때 확인해야 합니다. 이유는 [04-MinIO-현황과-선택.md](04-MinIO-현황과-선택.md)에 있습니다.

## 4. 서버가 이 상자들을 찾는 방법

서버 설정 파일(`application.yml`)에 **내 컴퓨터의 문 번호**를 적습니다. (가안)

| 대상 | 적는 주소 |
|---|---|
| DB | `localhost:5432` (데이터베이스 `myblog`) |
| Redis | `localhost:6379` |
| MinIO | `http://localhost:9000` (버킷 `myblog-images`) |

## 5. 하루 사용 순서

| 순서 | 할 일 | 명령 |
|---|---|---|
| 1 | Docker Desktop 앱을 켠다 (Mac) | (앱 실행) |
| 2 | 상자를 켠다 | `docker compose up -d` (`-d`는 뒤에서 조용히 돌린다는 뜻) |
| 3 | 잘 켜졌는지 본다 | `docker compose ps` (세 줄 모두 `healthy`) |
| 4 | 서버를 IntelliJ에서 실행한다 | |
| 5 | 화면을 실행한다 | `npm run dev` |
| 6 | 퇴근할 때 상자를 끈다 | `docker compose down` |

`down`으로 꺼도 **냉장고(데이터)는 남습니다.** 내일 다시 `up`하면 어제의 회원과 글이 그대로 있습니다.

| 자주 쓰는 명령 | 뜻 |
|---|---|
| `docker compose up -d` | 상자를 전부 켠다 |
| `docker compose down` | 상자를 끈다. **데이터는 남는다** |
| `docker compose down -v` | 상자와 **데이터까지 전부 지운다** (처음부터 다시 할 때만) |
| `docker compose logs minio` | 문제가 생겼을 때 MinIO 상자의 기록을 본다 |

## 6. 잘 켜졌는지 확인하는 법

| 대상 | 확인 방법 | 정상일 때 |
|---|---|---|
| DB | IntelliJ의 Database 창에서 접속 | 연결 성공 |
| Redis | `docker compose exec redis redis-cli ping` | `PONG` |
| MinIO | 브라우저에서 `http://localhost:9001` | 관리 화면이 열림 (커뮤니티판은 기능이 줄었을 수 있음) |

## 7. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop을 켜지 않음 | 앱을 켠 뒤 다시 실행 |
| `port is already allocated` (5432 등) | 내 컴퓨터에 이미 같은 번호를 쓰는 프로그램이 있음 | 주문서의 왼쪽 번호를 바꿈 (`"5433:5432"`) 후 서버 설정도 5433으로 |
| 데이터가 전부 사라짐 | `docker compose down -v`를 실행함 | `-v`는 냉장고까지 지우는 옵션이니 **처음부터 다시 할 때만** 씀 |
| 처음 켜는데 오래 걸림 | 이미지를 내려받는 중 | 처음에만 몇 분, 이후엔 빠름 |
| 서버가 DB에 접속하지 못함 | 상자가 아직 켜지는 중 | `docker compose ps`가 `healthy`가 될 때까지 기다림 |

## 8. Compose를 안 쓴다면

Compose는 편의 도구라서 필수가 아닙니다. DB와 Redis는 내 컴퓨터에 직접 설치해도 됩니다.

```bash
brew install postgresql@16 redis
brew services start postgresql@16
brew services start redis
```

다만 버전이 컴퓨터마다 달라질 수 있고 지우거나 초기화하기 번거롭습니다. 이미지 저장은 MinIO를 설치하는 대신 **서버 디스크 저장으로 바꿔 끼울 수 있습니다.** ([04-MinIO-현황과-선택.md](04-MinIO-현황과-선택.md) 참고)
