# 01. 서버와 접속 도구

> **한 줄 요약:** DB와 Redis와 MinIO는 **켜져 있어야 하는 서버 프로그램**입니다. IntelliJ의 DB 창이나 라이브러리는 거기에 **접속하는 도구**일 뿐, 서버 자체는 들어 있지 않습니다.
> 관련 파일: [02-도커-컴포즈-쿠버네티스.md](02-도커-컴포즈-쿠버네티스.md), [03-로컬환경-도커컴포즈-사용법.md](03-로컬환경-도커컴포즈-사용법.md)
> 읽는 순서는 [00-목차.md](00-목차.md)를 봅니다.

## 1. 전화에 빗대면

| | 비유 | 우리 프로젝트에서 |
|---|---|---|
| **서버 프로그램** | 전화를 **받는 사람** | PostgreSQL, Redis, MinIO |
| **라이브러리·IntelliJ** | 전화를 **거는 방법**(전화기) | DB 접속 코드(JDBC·JPA), Redis 접속 코드(Spring Data Redis), 이미지 저장소 접속 코드(S3 SDK), IntelliJ의 Database 창 |

전화기가 아무리 좋아도 **받는 사람이 없으면 통화가 안 됩니다.**

## 2. 부품별 정리

| 부품 | 접속하는 쪽 (우리가 추가) | 켜져 있어야 하는 쪽 (누군가 준비) |
|---|---|---|
| PostgreSQL | IntelliJ의 Database 창(들여다보는 화면), 서버 코드의 DB 접속 설정 | **PostgreSQL 서버 프로그램** |
| Redis | Spring Data Redis 같은 라이브러리 | **Redis 서버 프로그램** |
| MinIO | AWS S3 SDK 같은 라이브러리 | **MinIO 서버 프로그램** |

서버 프로그램이 꺼져 있는 채로 우리 서버를 실행하면 `Connection refused`(연결 거부) 같은 오류가 납니다.

## 3. 서버 프로그램을 켜는 방법

| 방법 | 설명 | 특징 |
|---|---|---|
| **Docker Compose** | 상자 여러 개를 한 줄 명령으로 켠다 | 한 번에 켜지고, 지우고 다시 만들기 쉽고, 모두 같은 환경 |
| **직접 설치** | `brew install postgresql@16 redis`처럼 설치한다 | DB와 Redis는 간단하지만 MinIO는 번거롭다 |
| **남이 켜 둔 서버에 접속** | 학교나 클라우드의 서버를 쓴다 | 설치는 필요 없지만 접속 정보를 받아야 한다 |

우리 프로젝트의 개발 환경은 **Docker Compose**를 가안으로 합니다. 자세한 방법은 [03-로컬환경-도커컴포즈-사용법.md](03-로컬환경-도커컴포즈-사용법.md)에 있습니다.

## 4. 예외

- **H2 같은 내장 DB**는 라이브러리만 추가해도 동작합니다. 하지만 우리는 로그인 세션 저장과 실제 운영 환경을 맞추기 위해 PostgreSQL을 쓰기로 했습니다.
- **내장 Redis 라이브러리**도 있지만 주로 테스트용이라 개발 환경으로는 권하지 않습니다.

## 5. 예전에는 왜 접속만 하면 됐나요?

예전 팀 프로젝트(aiot3)의 배포 설정에는 서버 프로그램이 아니라 **접속 정보**(`postgresdb-secret`, `redis-secret`, `minio-secret` 같은 이름)만 들어 있었습니다. 즉 **서버 프로그램은 이미 켜져 있었고** 우리 코드는 거기에 접속만 했습니다. 서버를 누가 켰는지는 그 자료만으로는 알 수 없습니다.

이번 프로젝트는 처음부터 공용 서버가 없으므로, **개발할 때는 내 컴퓨터에 서버 프로그램을 직접 켜야 합니다.** 배포할 때 누가 제공하는지는 [05-배포-준비.md](05-배포-준비.md)에서 확인할 것입니다.
