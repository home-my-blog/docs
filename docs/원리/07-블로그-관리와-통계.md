# 07. 블로그 관리와 통계: 동작 원리

> 기능 설명은 [기능/07-블로그-관리와-통계.md](../기능/07-블로그-관리와-통계.md)에 있어요. 2026-10-13 코드(develop) 기준이에요.

## 큰 흐름

### 흐름 1. 글을 열면 통계가 쌓여요

1. 브라우저가 `GET /api/posts/{id}`를 불러요.
2. 요청이 컨트롤러에 닿기 전에 `VisitorIdFilter`가 `MYBLOG_VID` 쿠키를 읽어요. 없으면 새 UUID(겹치지 않는 무작위 번호)를 만들어 1년짜리 쿠키로 내려 주고, 요청 속성 `myblog.vid`에 넣어 둬요.
3. `PostController.detail`이 글을 볼 수 있는지 확인한 뒤(`queries.requireVisible`) `ViewRecorder.record(글, 보는 회원 번호, vid)`를 불러요.
4. `ViewRecorder`가 Redis에 "이 사람이 이 글을 30분 안에 봤나"를 물어요. 처음이면 계속 진행해요.
5. 다시 Redis에 "이 사람이 오늘 이 블로그에 왔나"를 물어요.
6. PostgreSQL에 세 가지를 써요: `posts.view_count + 1`, `daily_stats`의 글별 줄 +1, `daily_stats`의 블로그 전체 줄 +1(새 방문자면 방문자도 +1).
7. 실시간 인기 검색어 계산용으로 `TrendingService.recordView`에 조회를 알려요(서버 메모리).
8. 글 내용이 응답으로 나가요.

### 흐름 2. 주인이 대시보드를 열어요

1. 브라우저가 `/manage`를 열면 `ManageLayout`이 로그인 정보(`GET /api/auth/me`)에서 블로그 번호와 새 댓글 수를 꺼내 메뉴를 그려요.
2. `DashboardPage`가 `GET /api/manage/dashboard`를 불러요.
3. `SecurityConfig`가 `/api/manage/**`는 로그인한 사람만 통과시켜요.
4. `ManageController.dashboard`가 `BlogService.requireOwnBlogId(로그인한 회원)`으로 **그 회원의 블로그 번호**를 찾아요.
5. `ManageService.dashboard`가 PostgreSQL에서 숫자를 모아요: 조회수·방문자 합계(`totals`), 새 댓글 수(`NewCommentCounter.count`), 날짜별 기록(`daily`), 인기 글(`PostQueryService.popularInBlog`), 최근 글.
6. JSON으로 돌려주면 화면이 숫자 카드와 recharts(리액트 그래프 라이브러리) 그래프를 그려요.

## 자세히 보기

### 주인 확인: 주소에 블로그 번호가 없어요

`ManageController`의 네 주소(`/api/manage/dashboard`, `/posts`, `/comments`, `/stats`)는 블로그 번호를 받지 않아요. `@AuthenticationPrincipal Long me`로 로그인한 회원 번호만 받고, `BlogService.requireOwnBlogId(me)`가 `SELECT id FROM blogs WHERE owner_id = ?`로 블로그를 찾아요. 블로그가 없으면 `BLOG_NOT_FOUND` 오류예요. 남의 블로그 번호를 넣을 칸 자체가 없으니, "주인인지 비교"하는 단계 없이도 남의 블로그를 볼 수 없어요.

화면 쪽은 `ManageLayout`이 `RequireLogin`으로 감싸고, `me.blog`가 없으면 `NotFound`를 보여 줘요. 하위 화면에는 `useManage()`로 블로그 번호를 넘겨요(`pages/manage/context.ts`).

### 조회수 중복 막기와 주인 제외 (`ViewRecorder.record`)

순서대로 이렇게 걸러요.

1. 글이 `PRIVATE`이거나, 보는 회원 번호가 글쓴이(`post.authorId`)와 같으면 바로 끝내요. 블로그는 회원마다 하나라서 글쓴이가 곧 블로그 주인이에요.
2. 회원 번호도 vid도 없으면 끝내요(쿠키 필터가 늘 vid를 넣어 주니 보통 일어나지 않아요).
3. 사람 구분값 `who`를 만들어요. 로그인했으면 `m:{회원번호}`, 아니면 `v:{vid}`예요(`visitorKey`). 그래서 같은 사람이라도 로그인 전후는 다른 사람으로 세요.
4. Redis `SET view:post:{글번호}:{who} 1 NX`를 30분 만료(`myblog.views.dedup`)로 해요. `setIfAbsent`는 키가 없을 때만 쓰고 true를 돌려줘요. false면 30분 안에 본 것이라 끝내요.
5. Redis `visit:{블로그번호}:{who}:{오늘 날짜}`를 같은 방식으로 쓰는데, 만료 시간은 `KoreanClock.untilMidnight()`, 곧 한국 시간 다음 자정까지 남은 시간이에요. 처음 쓰면 새 방문자예요.
6. DB에 더해요(아래 "daily_stats 집계").

방문자 검사는 조회가 새로 세질 때만 해요. 30분 안에 같은 글을 다시 열면 4번에서 끝나니까 방문자도 건드리지 않아요.

두 Redis 호출은 `RedisGuard.optional`로 감싸 있어요. Redis가 꺼져 있으면 예외 대신 빈 값이 오고 `orElse(false)`가 돼서, 4번에서 "새 조회 아님"으로 보고 **아무것도 세지 않아요**. 글 읽기 자체는 실패하지 않아요.

### 방문자 쿠키 (`VisitorIdFilter`)

`OncePerRequestFilter`(요청마다 한 번 도는 필터)예요. `shouldNotFilter`가 주소가 `/api/posts/`로 시작하지 않으면 건너뛰게 해서, 글 관련 요청에서만 동작해요. 쿠키 값은 `[0-9a-f-]{36}` 모양(UUID)일 때만 믿고, 아니면 새로 만들어요. 쿠키는 `Path=/`, `HttpOnly`(자바스크립트가 못 읽음), `SameSite=Lax`, `Max-Age` 365일이에요.

### daily_stats 집계

표 구조(`V1__core_schema.sql`에서 `daily_stat`으로 만들고 `V2`에서 `daily_stats`로 이름을 바꿈)는 이래요.

- `blog_id`, `post_id`(비어 있을 수 있음), `stat_date`(날짜), `views`, `visitors`
- 고유 인덱스 `(blog_id, post_id, stat_date) NULLS NOT DISTINCT`

한 번 조회하면 줄 두 개를 건드려요.

- **글별 줄** `(블로그, 글, 오늘)`: `views + 1`, 방문자는 0을 더해요. 인기 글 계산에 써요.
- **블로그 전체 줄** `(블로그, NULL, 오늘)`: `views + 1`, 새 방문자면 `visitors + 1`. 대시보드 숫자와 그래프에 써요.

`ViewRecorder.upsert`는 `INSERT ... ON CONFLICT (blog_id, post_id, stat_date) DO UPDATE SET views = daily_stats.views + EXCLUDED.views ...`예요. 그날 첫 조회면 줄을 새로 넣고, 이미 있으면 더해요. 보통 고유 인덱스는 NULL끼리 다르다고 봐서 `post_id`가 NULL인 줄이 날마다 여러 개 생길 수 있는데, `NULLS NOT DISTINCT`(PostgreSQL 15부터) 덕분에 NULL도 같은 값으로 보고 하루 한 줄만 남아요.

글별 줄은 `post_id`가 `ON DELETE CASCADE`라서 글을 지우면 같이 사라져요. 블로그 전체 줄은 남아서, 누적 숫자는 글을 지워도 줄지 않아요.

날짜는 `KoreanClock.today()`가 정해요. 서버 시계(UTC)의 지금 순간을 `Asia/Seoul`로 바꾼 날짜라서, 서버가 어느 나라에 있든 한국 자정에 날짜가 바뀌어요.

### 대시보드 숫자 (`ManageService.totals`, `dashboard`)

`totals(blogId, "views")`는 블로그 전체 줄(`post_id IS NULL`)만 골라 한 번의 SQL로 세 값을 내요.

- `today`: `stat_date = 오늘`인 줄의 값
- `yesterday`: `stat_date = 어제`인 줄의 값
- `total`: 모든 날의 합

`CASE WHEN ... END`를 `sum` 안에 넣는 방식이라 표를 한 번만 읽어요. 방문자도 같은 메서드에 열 이름만 바꿔 불러요. 그래서 누적 방문자는 "날마다의 방문자 합"이에요.

`dashboard`는 이 둘에 더해 `NewCommentCounter.count`, `daily(blogId, chartDays)`, 인기 글, 최근 글(`posts`를 `created_at DESC, id DESC`로 `recent-size`개)을 `LinkedHashMap`에 담아 돌려줘요. 설정값은 `MyBlogProperties`의 `dashboard()`에서 읽어요.

### 인기 글 7일 5개 (`PostQueryService.popularInBlog`)

`daily_stats`의 **글별 줄**을 `posts`와 이어 붙여(`JOIN`) `stat_date >= 오늘 - (popular-days - 1)`인 것만 글마다 `sum(views)`해요. 7이면 오늘 포함 7일이에요. 조건에 `PUBLIC_ONLY`를 붙여서 글이 `PUBLIC`이고, 다이어리가 공개이고, 글쓴이가 탈퇴하지 않은 글만 남겨요. 조회수 많은 순, 같으면 글 번호 큰 순으로 `popular-size`개를 잘라요. 화면의 숫자는 전체 조회수가 아니라 이 기간의 조회수예요.

### 날짜별 기록 (`ManageService.daily`)

그래프용 날짜 목록을 만들어요.

1. `from = 오늘 - (days - 1)`을 정해요.
2. 블로그 전체 줄에서 `stat_date >= from`인 조회수·방문자를 읽어 날짜별 `Map`에 넣어요.
3. 댓글은 따로 세요. `comments`와 `posts`를 이어 이 블로그 글의 댓글 중 `created_at >= from의 한국 자정`인 것을 `(created_at AT TIME ZONE 'Asia/Seoul')::date`로 묶어 셉니다. 저장 시각은 UTC라서 한국 날짜로 바꿔야 그날 밤 11시 댓글이 다음 날로 넘어가지 않아요.
4. `from`부터 오늘까지 하루씩 돌며 `Map`에 없는 날은 0으로 채워요.

그래서 응답은 늘 정확히 7개나 30개예요. 댓글은 통계 표가 아니라 지금 남은 `comments`에서 세니까, 내 댓글도 들어가고 지운 댓글은 빠져요.

`GET /api/manage/stats?days=N`은 `days == 7 ? 7 : 30`으로 7이 아니면 모두 30으로 바꿔 같은 `daily`를 불러요. `StatsPage`는 받은 목록을 그대로 그래프에 넣고, 합계 카드는 화면에서 `reduce`로 더해요.

### 새 댓글 수 (`NewCommentCounter`)

`blogs.comments_seen_at`(댓글 관리를 마지막으로 연 시각) 한 칸으로 셉니다. 블로그를 만들 때(`BlogService.createFor`) 지금 시각을 넣어 둬서 비어 있지 않아요.

```sql
SELECT count(*) FROM comments cm JOIN posts p ON p.id = cm.post_id JOIN blogs b ON b.id = p.blog_id
WHERE b.id = ? AND cm.created_at > b.comments_seen_at AND cm.author_id IS DISTINCT FROM ?
```

`IS DISTINCT FROM`은 NULL도 비교할 수 있는 "다르다"예요. `comments.author_id`는 `ON DELETE SET NULL`이라 NULL이 될 수 있는 칸이에요. `<>`로 쓰면 NULL 줄이 빠지지만, 이 식은 NULL도 "주인이 아님"으로 세요. (지금 코드에는 회원 줄을 지우는 곳이 없어서, 탈퇴해도 실제로 NULL이 되지는 않아요.)

이 클래스는 두 곳에서 불려요. `ManageService.dashboard`와 `AuthController`의 로그인 정보 응답(`newCommentCount`)이에요. 화면의 이름 메뉴(`UserMenu`), 홈 계정 상자(`HomePage`), 관리 메뉴(`ManageLayout`)는 모두 로그인 정보의 숫자를 써요. `useMe`의 `staleTime`이 60초라서 다른 화면에서는 최대 1분 늦게 바뀔 수 있어요.

### 댓글 관리와 읽음 처리 (`ManageService.comments`)

`@Transactional`(한 묶음으로 처리) 메서드예요.

1. 지금의 `comments_seen_at`을 먼저 읽어요.
2. 이 블로그 글의 댓글 수를 세고, `PageRequests.page`로 쪽을 나눠 최신순으로 읽어요. 쓴 사람이 탈퇴 중(`members.deleted_at`이 있음)이면 `author_id`를 NULL로 바꿔 내려서 화면이 "탈퇴한 사용자"로 보여 줘요.
3. 줄마다 `isNew = 작성 시각 > 1번의 시각 && (탈퇴한 사람이거나 주인이 아님)`을 계산해요. 미리보기는 공백을 한 칸으로 줄인 뒤 `Texts.cut`으로 50자까지 잘라요.
4. 마지막에 `UPDATE blogs SET comments_seen_at = 지금`을 해요.

먼저 옛 시각으로 NEW를 표시한 뒤에 시각을 갱신하는 순서라서, 처음 연 화면에는 NEW가 보이고 다음부터는 안 보여요. 몇 쪽을 열든 시각이 지금으로 바뀌니 새 댓글이 전부 읽음이 돼요.

화면(`CommentsPage`)은 이 순서를 지키려고 몇 가지를 해요.

- 쿼리를 `staleTime: Infinity, gcTime: 0`으로 둬요. 같은 화면에 있는 동안 다시 받지 않아 NEW가 사라지지 않고, 떠나면 바로 버려요.
- 받아 오기에 성공하면 `qk.me`와 `qk.dashboard`를 무효화해서 배지를 바로 다시 받아요.
- 댓글을 지우면 목록을 다시 받지 않고 `setQueryData`로 그 줄만 빼요. 다시 받으면 이미 읽음이라 NEW가 다 꺼지기 때문이에요.

### 글 관리 목록 (`ManageService.posts`)

`WHERE p.blog_id = :blog`에서 시작해, `visibility`가 `PUBLIC`/`SUBSCRIBERS`/`PRIVATE` 중 하나일 때만 조건을 더하고(다른 값은 무시), `categoryId`가 있으면 다이어리 조건을 더해요. 이름 붙은 매개변수(`:vis`, `:cat`)로 넣어서 사용자가 보낸 값이 SQL 글자로 섞이지 않아요. 방문자용 목록과 달리 공개 여부로 거르지 않아서 비공개 글도 나와요. 댓글 수는 줄마다 하위 쿼리로 세요.

화면(`PostsPage`)은 거르기 값을 `useSearchParams`로 주소에 넣어요. 거르기를 바꾸면 `page`를 지워 1쪽으로 가요. 하나 지우기는 일반 글 삭제(`deletePost`)를 부른 뒤 `['manage']`, `['blog']` 쿼리를 무효화해요.

### 한꺼번에 옮기기·지우기 (`PostCommandService`)

주소는 `POST /api/blogs/{blogId}/posts/move`와 `POST /api/blogs/{blogId}/posts/delete`이고, 몸통은 `{ postIds, categoryId }`예요(`PostController.BulkRequest`). 화면은 `BlogPage`의 `DiaryEditList`예요.

공통 검사 `requireOwnPosts`:

1. `blogs.requireOwner(blogId, me)`로 주인이 아니면 "없는 블로그"와 같은 오류를 내요.
2. `postIds`에서 겹친 번호를 빼고, 비어 있으면 `postIds` 칸 오류예요.
3. `blog_id = 이 블로그 AND author_id = 나 AND id IN (...)`인 글 수가 보낸 개수와 다르면 `POST_NOT_FOUND`예요. 하나라도 남의 글이면 통째로 거절해요.

`movePosts`는 다이어리가 이 블로그 것인지 확인하고 `UPDATE posts SET category_id`만 해요. `updated_at`을 건드리지 않아서 수정 시각이 그대로예요. `deletePosts`는 먼저 사진 저장 키를 모아 두고 `DELETE FROM posts`를 해요. 댓글·좋아요·태그 연결은 외래 키(FK)의 `ON DELETE CASCADE`로 같이 지워지고, 사진 파일은 `images.deleteFilesAfterCommit`으로 DB 커밋이 끝난 뒤에 지워요. DB가 실패해서 되돌려졌는데 파일만 사라지는 일을 막기 위해서예요. 둘 다 `@Transactional`이에요.

### /api/config (`ConfigController`)

`MyBlogProperties`(application.yml의 `myblog.*`를 담는 설정 객체)에서 값을 꺼내 `limits`, `pageSize`, `trendingIntervalSeconds`, `draftLimit`, `draftAutosaveSeconds`, `topics`로 묶어 돌려줘요. 책갈피 폴더 이름 길이만 설정이 아니라 `BookmarkService.FOLDER_NAME_MAX` 상수예요. `GET /api/**`는 누구나 부를 수 있어서 로그인 없이도 받아요.

화면은 `useConfig()`(`api/queries.ts`)가 `staleTime: Infinity, retry: 1`로 한 번 받아 계속 써요. 받은 값은 `mergeConfig`(`lib/config.ts`)가 `DEFAULT_CONFIG` 위에 덮어써요. 서버가 응답하지 않거나 칸이 빠져도 화면이 깨지지 않게 하려는 거예요. 다이어리 관리(`CategoriesPage`)와 블로그 설정(`SettingsPage`)도 이 값으로 길이를 먼저 검사해요.

## 데이터는 어디에

| 무엇 | 어디에 | 언제 사라지나 |
|---|---|---|
| 날짜별 블로그 조회수·방문자 | PostgreSQL `daily_stats` (`post_id` NULL 줄) | 블로그가 지워질 때 |
| 날짜별 글 조회수 | PostgreSQL `daily_stats` (`post_id` 있는 줄) | 글이 지워질 때 |
| 글 전체 조회수 | PostgreSQL `posts.view_count` | 글이 지워질 때 |
| 30분 중복 조회 표시 `view:post:{글}:{who}` | Redis | 30분 뒤 |
| 오늘 방문 표시 `visit:{블로그}:{who}:{날짜}` | Redis | 한국 시간 다음 자정 |
| 방문자 구분값 `MYBLOG_VID` | 브라우저 쿠키 | 1년 뒤, 또는 사용자가 지울 때 |
| 댓글 관리를 마지막으로 연 시각 | PostgreSQL `blogs.comments_seen_at` | 블로그가 지워질 때 (댓글 관리를 열 때마다 바뀜) |
| 날짜별 댓글 수 | 따로 저장 안 함, `comments`에서 그때그때 셈 | 댓글이 지워지면 숫자도 줄어요 |
| 실시간 인기 계산용 최근 조회 | 서버 메모리 (`TrendingService`) | 집계 창(24시간)이 지나거나 서버가 다시 뜰 때 |
| 서버 기본값 | 브라우저 메모리 (React Query 캐시) | 페이지를 새로 열 때 |

## 왜 이렇게 만들었나

- **조회할 때 DB에 바로 더하기**: research.md §9는 "규모가 작아 바로 DB에 쓴다"고 정했어요. Redis에 모았다가 주기적으로 옮기는 방식은 느려지면 바꿀 대안으로 남겨 뒀어요. 바로 쓰면 대시보드 숫자가 늘 최신이고, 스케줄러가 필요 없어요.
- **중복 막기는 Redis 만료 키로**: "30분", "자정까지"처럼 저절로 사라져야 하는 표시라 만료 시간(TTL)이 있는 Redis가 맞아요(research.md §9, 상세/06 구현 방식). DB에 두면 지우는 일을 따로 돌려야 해요.
- **Redis가 꺼지면 세지 않기**: 조회수는 없어도 되는 일이라 `RedisGuard.optional`로 건너뛰어요. 글 읽기가 실패하는 것보다 숫자가 조금 빠지는 게 낫다고 봤어요.
- **비로그인은 쿠키로**: 로그인하지 않은 사람도 같은 사람을 알아봐야 해서 1년짜리 UUID 쿠키를 써요(research.md §9).
- **글별 줄과 블로그 줄을 따로**: 블로그 전체 숫자를 매번 글별 줄에서 더하지 않고 한 줄로 바로 읽으려고요. 방문자는 블로그 단위라 글별로 나눌 수 없어서 블로그 줄에만 있어요.
- **새 댓글은 시각 한 칸으로**: 상세/06 구현 방식에서 정한 대로, 댓글마다 읽음 표시를 두지 않고 "마지막으로 연 시각" 하나와 비교해요. 칸 하나로 끝나서 단순해요. 대신 하나씩 읽음 처리는 할 수 없어요.
- **관리 주소에 블로그 번호를 받지 않기**: 로그인한 회원에서 블로그를 찾으면 "남의 블로그" 경우가 처음부터 없어요(BM-01-2).
- **화면 제한값을 서버에서 받기**: `ConfigController` 주석이 FR-039, NF-08(기본값은 바꿀 수 있어야 함)을 가리켜요. 숫자를 한곳(application.yml)에서만 바꾸면 화면도 따라와요.

## 공부 키워드

- `INSERT ... ON CONFLICT DO UPDATE`: PostgreSQL의 upsert, 있으면 고치고 없으면 넣기
- `NULLS NOT DISTINCT`: PostgreSQL 15 고유 인덱스에서 NULL을 같은 값으로 보기
- `IS DISTINCT FROM`: NULL까지 안전하게 비교하는 SQL 연산자
- `AT TIME ZONE`: timestamptz를 특정 지역 시각으로 바꾸기
- Redis `SET NX EX` (`setIfAbsent`): 없을 때만 쓰고 만료 시간 붙이기
- Spring `OncePerRequestFilter`: 요청마다 한 번 도는 서블릿 필터
- `@AuthenticationPrincipal`: Spring Security에서 로그인한 사용자 꺼내기
- `@Transactional`과 커밋 뒤 작업(`TransactionSynchronization`)
- TanStack Query `staleTime` / `gcTime` / `invalidateQueries` / `setQueryData`
- recharts `LineChart`, `BarChart`, `ResponsiveContainer`
