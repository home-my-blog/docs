# 04. 읽기와 소통: 동작 원리

> 기능 설명은 [기능/04-읽기와-소통.md](../기능/04-읽기와-소통.md)에 있어요. 2026-10-13 코드(develop) 기준이에요.

## 큰 흐름

### 글 하나를 열 때

1. 브라우저가 `/posts/12`로 가면 `PostDetailPage`가 `GET /api/posts/12`를 보내요. GET 요청은 로그인 없이도 통과해요(`SecurityConfig`).
2. 요청이 컨트롤러에 닿기 전에 `VisitorIdFilter`가 `MYBLOG_VID` 쿠키를 확인해요. 없으면 새 UUID(겹치지 않는 무작위 번호)를 만들어 1년짜리 쿠키로 내려 주고, 요청에 그 값을 붙여 둬요.
3. `PostController.detail`이 `PostQueryService.requireVisible`로 "이 사람이 이 글을 볼 수 있나"를 SQL 한 번으로 확인해요. 못 보면 `POST_NOT_FOUND`(404)로 끝나요.
4. `ViewRecorder.record`가 조회수와 방문자를 세요. Redis에 "30분 안에 본 적 있음" 표시를 남기고, 처음이면 PostgreSQL의 `posts.view_count`와 `daily_stats`를 올려요.
5. 컨트롤러가 블로그 정보, 태그, 좋아요 수와 내가 눌렀는지, 내 책갈피, 댓글 수, 이전/다음 글(`neighbors`), 다른 글 3개(`otherPosts`), 내 글인지(`isAuthor`), 대표글인지를 모아서 JSON으로 돌려줘요.
6. 화면은 TanStack Query(서버 데이터를 캐시해 두는 React 라이브러리)에 60초 동안 담아 두고 그려요. 댓글은 `CommentSection`이 `GET /api/posts/12/comments`로 따로 받아요.

### 댓글을 달 때

1. `CommentSection`의 입력칸에서 등록을 누르면 `POST /api/posts/12/comments`에 `{ body, parentId }`를 보내요. POST는 로그인해야 통과해요.
   - 화면은 보내기 전에 `lib/validation.ts`의 `charCount`(`[...s].length`, 코드 포인트 단위)로 길이를 먼저 봐요. 서버의 `Texts.length`와 같은 방법이라 이모지도 1자예요(v1.7.1). 입력칸 아래 "N/500"도 이 함수로 세요.
2. `CommentService.create`가 차례로 검사해요. 이 메서드는 `@Transactional`이에요(v1.7.1).
   - 글을 볼 수 있나 (`requireVisible`)
   - `parentId`가 있으면, 같은 글의 **원 댓글**인가 (답글의 답글 막기)
   - 앞뒤 빈칸을 지운 본문이 1~500자인가
   - Redis `comment:cooldown:{회원번호}`를 5초짜리로 만들 수 있나 (이미 있으면 5초 안에 또 단 것 → 429 `COMMENT_TOO_SOON`)
3. `comments` 표에 넣고, `InkService.rewardComment`로 잉크를 줘요(남의 글일 때만). `rewardComment`도 `@Transactional`(기본 전파 REQUIRED)이라 `create`의 트랜잭션에 합류해요. 그래서 댓글과 잉크가 한 번에 확정되고, 잉크 적립이 실패하면 댓글도 되돌아가요.
4. 방금 넣은 댓글을 다시 읽어서 돌려주고, 화면은 댓글 목록을 다시 받아요.

## 자세히 보기

### 볼 수 있는 글: SQL 조건 두 개

글을 읽는 모든 곳은 `PostQueryService`를 거쳐요. 공개 범위 조건은 SQL 조각 두 개로 정해져 있어요.

- `PUBLIC_ONLY`: 글이 `PUBLIC`이고, 다이어리도 `PUBLIC`이고(`OPEN_CATEGORY`), 글쓴이가 탈퇴 신청을 하지 않았어요(`ACTIVE_AUTHOR`). 홈, 검색, 태그, 인기 글, **이전/다음 글, 다른 글 3개**가 이걸 써요.
- `VISIBLE_TO`: 위 조건이거나, 내가 쓴 글이거나(`p.author_id = :viewer`), 구독자로서 볼 수 있는 글(`SUBSCRIBER_VISIBLE`)이에요. 그리고 언제나 `ACTIVE_AUTHOR`. 글 상세, 블로그 글 목록, 구독 피드, 책갈피 목록이 이걸 써요.

`SUBSCRIBER_VISIBLE`은 "글이 비공개가 아니고, 다이어리도 비공개가 아니고, 그 블로그(`subscriptions`)나 그 다이어리(`diary_subscriptions`)를 내가 구독했다"는 뜻이에요. 그래서 비공개 다이어리의 글은 글이 공개여도 주인만 봐요.

로그인하지 않은 사람은 `:viewer`에 `-1`을 넣어요(`viewerParam`). 어떤 회원 번호와도 같지 않으니 "내 글"과 "구독" 조건이 저절로 거짓이 돼요. 이 조건을 SQL 문자열 상수로 두고 여러 클래스(`BookmarkService`, `SubscriptionService`)가 가져다 붙여 써서, 볼 수 있는 기준이 한 곳에서만 정해져요.

볼 수 없는 글은 403(권한 없음)이 아니라 404(없음)로 답해요. 그래야 비공개 글이 있다는 사실도 새지 않아요.

### 이전/다음 글과 다른 글 3개

`PostQueryService.neighbors`는 같은 블로그의 `PUBLIC_ONLY` 글 중에서 `(created_at, id)` 짝을 지금 글과 비교해요.

- 이전 글: `(created_at, id) < (지금 글)`을 최신순으로 정렬해 1개
- 다음 글: `(created_at, id) > (지금 글)`을 오래된 순으로 정렬해 1개

`created_at`만 비교하면 같은 시각에 쓴 글끼리 순서가 꼬일 수 있어서 `id`를 함께 비교해요. PostgreSQL의 행 값 비교(row value comparison)라서 두 칸을 한 번에 비교할 수 있어요.

`otherPosts`는 같은 블로그의 `PUBLIC_ONLY` 글 중 지금 글을 뺀 최신 `myblog.post.other-posts`(3)개예요.

### 공유 버튼 (화면만)

`PostDetailPage`의 `share` 함수가 처리해요. 서버는 관여하지 않아요.

1. 주소를 `window.location.origin + '/posts/' + id`로 만들어요.
2. `navigator.share`가 함수로 있으면 그걸 불러요(Web Share API, 휴대폰의 공유 창).
3. 없으면 `navigator.clipboard.writeText`로 복사하고 알림을 띄워요.
4. 사용자가 공유 창을 닫으면 `AbortError`가 나는데, 이건 조용히 넘어가요. 다른 오류(복사 권한 없음 등)면 `window.prompt`로 주소를 보여 줘요.

### 조회수와 방문자 세기: `ViewRecorder.record`

1. 비공개 글이거나, 보는 사람이 글쓴이면 바로 끝나요. 회원도 아니고 쿠키 값도 없으면 끝나요.
2. "누구"를 정해요(`visitorKey`). 로그인했으면 `m:{회원번호}`, 아니면 `v:{쿠키 UUID}`.
3. Redis에 `view:post:{글번호}:{누구}`를 **SET NX**(없을 때만 만들기)로 30분짜리로 만들어요. 이미 있으면 30분 안에 본 것이라 끝나요.
4. 새 조회면 `visit:{블로그번호}:{누구}:{오늘 날짜}`를 역시 SET NX로 만드는데, 수명은 한국 시간 다음 날 0시까지예요(`KoreanClock.untilMidnight`). 새로 만들어졌으면 오늘 처음 온 방문자예요.
5. PostgreSQL에 바로 써요.
   - `posts.view_count += 1`
   - `daily_stats`에 (블로그, **이 글**, 오늘) 줄: 조회 +1
   - `daily_stats`에 (블로그, **글 없음(NULL)**, 오늘) 줄: 조회 +1, 새 방문자면 방문자 +1
6. `TrendingService.recordView`로 서버 메모리의 최근 조회 목록에도 넣어요. 실시간 인기 검색어 점수에 그 검색어가 제목에 든 글의 조회 수가 들어가기 때문이에요.

`daily_stats`는 `INSERT ... ON CONFLICT (blog_id, post_id, stat_date) DO UPDATE`로 "없으면 만들고, 있으면 더하기"를 한 문장에 해요. `post_id`가 NULL인 블로그 전체 줄도 날짜마다 하나만 있게 하려고, 고유 인덱스에 `NULLS NOT DISTINCT`(NULL끼리도 같다고 보기, PostgreSQL 15부터)를 붙였어요(V1).

SET NX는 "확인하고 쓰기"를 Redis가 한 번에 해 줘서, 같은 사람이 동시에 두 번 열어도 한 번만 세요.

글 상세 응답의 `viewCount`는 `requireVisible`에서 이미 읽어 둔 값이라, 이번 조회가 더해지기 전 숫자예요.

### `MYBLOG_VID` 쿠키: `VisitorIdFilter`

- `OncePerRequestFilter`(요청마다 한 번 도는 필터)예요. `shouldNotFilter`로 주소가 `/api/posts/`로 시작하는 요청에만 돌아요.
- 쿠키 값이 UUID 모양(`[0-9a-f-]{36}`)이 아니면 없는 것으로 보고 새로 만들어요. 아무 값이나 넣어서 Redis 키를 어지럽히지 못하게요.
- 쿠키 설정: `Path=/`, `HttpOnly`(자바스크립트가 못 읽음), `SameSite=Lax`, `Max-Age` 365일.
- 값은 `myblog.vid`라는 요청 속성(attribute)으로 넘겨서 컨트롤러가 꺼내 써요.

### Redis가 꺼졌을 때: `RedisGuard.optional`

조회 기록과 댓글 간격 검사는 `RedisGuard.optional`로 감싸 있어요. Redis 오류가 나면 로그만 남기고 빈 값을 돌려줘요.

- 조회: `.orElse(false)`라서 "새 조회 아님"으로 보고 **세지 않아요**. 글은 정상으로 열려요.
- 댓글 간격: `.orElse(true)`라서 "등록해도 됨"으로 보고 **검사를 건너뛰어요**.

다만 로그인 세션이 Redis에 있으니, Redis가 꺼지면 댓글 쓰기 자체가 로그인 문제로 막혀요.

### 댓글 목록을 한 번에 읽기: `CommentService.list`

답글이 한 단계뿐이라 재귀 쿼리 없이 정렬 하나로 "원 댓글, 그 답글들, 다음 원 댓글..." 순서를 만들어요.

```sql
ORDER BY COALESCE(cm.parent_id, cm.id), cm.parent_id NULLS FIRST, cm.created_at, cm.id
```

- `COALESCE(parent_id, id)`: 원 댓글은 자기 번호, 답글은 부모 번호. 그래서 한 가족이 붙어서 나와요.
- `parent_id NULLS FIRST`: 가족 안에서 원 댓글이 맨 앞.
- 그다음 쓴 시각 순.

자바에서는 줄을 차례로 돌며 원 댓글을 만나면 새 `replies` 목록을 만들고, 답글은 바로 앞 원 댓글의 `replies`에 넣어요.

작성자 표시는 SQL에서 정해요. `CASE WHEN m.deleted_at IS NULL THEN cm.author_id END`라서 탈퇴를 신청했거나 익명화된 회원이면 `author_id`가 NULL이 되고, 응답의 `author`가 `null`이 돼요. 화면(`CommentSection`)은 `author`가 없으면 "탈퇴한 사용자"를 써요. 회원 줄을 지우지 않고 `deleted_at`으로 표시만 하기 때문에(V4), 보관 기간 안에 복구하면 닉네임이 다시 보여요.

`canDelete`는 서버가 줄마다 계산해요: 보는 사람이 작성자이거나 그 블로그 주인이면 `true`.

### 댓글 지우기: `CommentService.delete`

1. 댓글을 읽어요. 없으면 404.
2. 작성자도 블로그 주인도 아니면 **역시 404**(`COMMENT_NOT_FOUND`)로 답해요. 남의 댓글이 있는지 알려 주지 않으려고요.
3. `DELETE FROM comments WHERE id = ?`. 답글은 `parent_id`의 외래 키가 `ON DELETE CASCADE`(V3)라서 DB가 같이 지워요.

화면은 지운 원 댓글의 답글 수만큼 댓글 수를 같이 빼요.

### 좋아요: `InteractionService.toggleLike`

1. 글을 볼 수 있나 확인하고, 내 글이면 `OWN_POST`(400).
2. 먼저 `DELETE`를 해 봐요. 지워진 줄이 있으면 "취소"예요.
3. 지워진 줄이 없으면 `INSERT ... ON CONFLICT DO NOTHING`으로 넣어요. 같은 사람이 동시에 두 번 눌러도 기본 키 `(post_id, member_id)` 때문에 한 줄만 남아요.
4. `{ liked, likeCount }`를 돌려주고, `LikeButton`은 이 값을 캐시에 바로 써 넣어요(`setQueryData`). 글을 다시 받아 오지 않아요.

구독 버튼(`SubscriptionService.toggle`, `toggleDiary`)도 같은 "지워 보고, 없었으면 넣기" 방식이에요.

### 신고: `InteractionService.report`

1. 글을 볼 수 있나, 내 글이 아닌가 확인해요.
2. 사유가 `SPAM`, `ABUSE`, `ADULT`, `OTHER` 중 하나인가 확인해요. DB에도 같은 CHECK 조건이 있어요(V1).
3. 설명은 `OTHER`일 때만 받고, 다른 사유면 빈 값으로 저장해요. 200자를 넘으면 오류.
4. `post_flags`에 넣어요. `(post_id, reporter_id)` 고유 조건에 걸리면 `DuplicateKeyException`을 잡아 `ALREADY_REPORTED`(409)로 바꿔요.

처음 표 이름은 `post_report`였는데 "보고서"로 읽힌다는 이유로 V2에서 `post_flags`로 바꿨어요. 신고를 읽는 코드나 화면은 없어요.

### 책갈피와 폴더: `BookmarkService`

- **꽂기·옮기기** (`PUT /api/posts/{id}/bookmark`, 본문 `{ folderId }`): 글을 볼 수 있는지, 폴더가 내 것인지 확인한 뒤 `INSERT ... ON CONFLICT (member_id, post_id) DO UPDATE SET folder_id = ...`. 처음이면 꽂고, 이미 있으면 폴더만 바꿔요. 꽂은 시각(`created_at`)은 처음 꽂을 때 그대로 남아요.
- **빼기** (`DELETE /api/posts/{id}/bookmark`): 없어도 성공으로 답해요.
- **목록** (`GET /api/me/bookmarks?folder=all|none|{번호}`): `PostQueryService.bookmarks`가 `VISIBLE_TO`로 거르기 때문에 지금 볼 수 없는 글은 빠져요. 그 뒤 글마다 꽂은 시각(`savedAt`)과 폴더를 붙여요.
- **폴더 탭 개수** (`GET /api/me/bookmark-folders`): `VISIBLE_BOOKMARK` 조건으로 볼 수 있는 글만 세요. 전체, 미분류(`folder_id IS NULL`), 폴더마다.
- **폴더 만들기·이름 바꾸기·지우기** (`POST`, `PATCH`, `DELETE /api/me/bookmark-folders`): 이름은 앞뒤 빈칸을 지우고 1~20자, "전체"·"미분류" 금지. 같은 이름은 DB 고유 조건 `(member_id, name)`에 걸리면 409로 바꿔요. 폴더를 지우면 `bookmarks.folder_id`가 `ON DELETE SET NULL`(V16)이라 안의 책갈피가 미분류가 돼요.
- 남의 폴더 번호를 넣으면 "없는 폴더"(404)로 답해요(`requireFolder`).

### 구독: `SubscriptionService`

- **블로그 구독** (`PUT /api/blogs/{id}/subscribe`): 내 블로그면 `OWN_BLOG`. 토글하고 `{ subscribed, subscriberCount }`를 돌려줘요.
- **다이어리 구독** (`PUT /api/categories/{id}/subscribe`): 내 다이어리면 `OWN_DIARY`, 비공개면 `PRIVATE_DIARY`. 구독자만 다이어리는 새로 구독할 때만 블로그 구독 여부를 확인해서 `SUBSCRIBERS_ONLY_DIARY`(403)를 내요. 취소는 언제나 돼요.
- 구독자 수는 `members.deleted_at IS NULL`인 회원만 세요.
- 다이어리를 비공개로 바꾸면 `CategoryService`가 그 다이어리의 `diary_subscriptions`를 지워요.
- **구독 화면**: `GET /api/me/subscriptions`(블로그 목록), `GET /api/me/subscriptions/diaries`(다이어리 목록), `GET /api/me/subscriptions/posts?kind=all|diary|blog&page=`(글). `PostQueryService.subscriptionFeed`는 `kind`에 따라 "구독한 블로그의 글" / "구독한 다이어리의 글" / 둘의 OR 조건에 `VISIBLE_TO`를 붙여요. OR 조건 하나로 거르기 때문에 두 쪽에 다 걸린 글도 한 번만 나와요.
- `SubscriptionsPage`는 탭을 주소의 `?kind=`로 기억해서, 새로고침해도 같은 탭이 열려요.

## 데이터는 어디에

| 무엇 | 어디에 | 언제 사라지나 |
|---|---|---|
| 조회수 합계 | PostgreSQL `posts.view_count` | 글을 지울 때 |
| 날짜별 조회·방문자 | PostgreSQL `daily_stats` (글별 줄 + `post_id` NULL인 블로그 전체 줄) | 블로그나 글이 지워질 때(CASCADE) |
| 30분 중복 조회 표시 | Redis `view:post:{글}:{m:회원 또는 v:UUID}` | 30분 뒤 |
| 오늘 방문 표시 | Redis `visit:{블로그}:{누구}:{yyyy-MM-dd}` | 한국 시간 자정 |
| 방문자 구분값 | 브라우저 쿠키 `MYBLOG_VID` | 1년 뒤, 또는 사용자가 지울 때 |
| 댓글·답글 | PostgreSQL `comments` (`parent_id`로 답글 연결) | 지울 때, 글이 지워질 때. 원 댓글을 지우면 답글도 |
| 댓글 5초 간격 표시 | Redis `comment:cooldown:{회원}` | 5초 뒤 |
| 좋아요 | PostgreSQL `post_likes` (기본 키 글+회원) | 취소할 때, 글이 지워질 때 |
| 신고 | PostgreSQL `post_flags` | 글이 지워질 때 |
| 책갈피 | PostgreSQL `bookmarks` (기본 키 회원+글, `folder_id`) | 뺄 때, 글이 지워질 때 |
| 책갈피 폴더 | PostgreSQL `bookmark_folders` | 폴더를 지울 때 |
| 블로그 구독 | PostgreSQL `subscriptions` | 취소할 때, 블로그가 지워질 때 |
| 다이어리 구독 | PostgreSQL `diary_subscriptions` | 취소할 때, 다이어리가 지워지거나 비공개가 될 때 |
| 최근 조회 목록(인기 검색어용) | 서버 메모리 `TrendingService` | 서버를 다시 켤 때 |
| 글 상세 캐시 | 브라우저 메모리(TanStack Query) | 60초 뒤 낡은 것으로 보고 다시 받음 |
| 읽은 글 기록(추천용) | 브라우저 localStorage (`lib/readHistory`) | 사용자가 지울 때 |

## 왜 이렇게 만들었나

- **조회수를 바로 DB에 쓰기**: research.md 9장에 따르면 Redis에 모았다가 주기적으로 DB에 옮기는 방법도 생각했지만, 규모가 작아서 바로 쓰기로 했어요. 느려지면 그때 바꾸기로 했어요.
- **방문자 구분에 쿠키 쓰기**: 로그인하지 않은 사람도 30분 중복 제거를 하려면 구분값이 필요해요. IP 대신 1년짜리 UUID 쿠키를 써요(research.md 9장).
- **Redis가 꺼져도 글은 열리게**: 조회수는 틀려도 큰일이 아니라서 `RedisGuard.optional`로 건너뛰어요. 인증번호처럼 꼭 Redis가 있어야 하는 일만 `required`로 막아요(`RedisGuard` 주석).
- **답글은 한 단계만**: 깊이가 하나면 재귀 쿼리 없이 정렬 하나로 읽을 수 있어요(V3 주석).
- **탈퇴 회원 댓글을 남기기**: 회원 줄을 바로 지우지 않고 `deleted_at`으로 표시만 해요(V4). 보관 기간에는 복구할 수 있고, 지나면 개인정보만 지우고(익명화) 다른 사람 글에 단 댓글은 "탈퇴한 사용자"로 남아요.
- **없는 것처럼 답하기(404)**: 볼 수 없는 글, 남의 댓글, 남의 폴더 모두 404로 답해서 존재 여부가 새지 않게 했어요(`requireVisible`, `CommentService.delete`, `requireFolder` 주석).
- **신고는 `flag`**: "report"가 보고서로 읽혀서 표 이름을 바꿨어요(V2 주석).
- **입력 검사는 서비스 코드에서**: 길이, 사유, 폴더 이름 같은 검사는 Bean Validation이 아니라 각 서비스가 직접 하고, 글자 수는 `Texts.length`로 코드 포인트(이모지도 한 글자) 단위로 세요. 화면의 `charCount`도 같은 단위로 세서, 화면과 서버의 판단이 어긋나지 않아요.

## 공부 키워드

- **Redis SET NX + TTL**: 없을 때만 키를 만들고 수명을 거는 명령. 중복 제거와 간격 제한에 써요.
- **PostgreSQL UPSERT (`ON CONFLICT DO UPDATE`)**: 없으면 넣고 있으면 고치는 한 문장.
- **`NULLS NOT DISTINCT`**: 고유 인덱스에서 NULL끼리도 같은 값으로 보게 하는 PostgreSQL 15 기능.
- **Row value comparison**: `(a, b) < (x, y)`처럼 여러 칸을 한꺼번에 비교하기. 이전/다음 글에 써요.
- **`ON DELETE CASCADE` / `SET NULL`**: 부모 줄이 지워질 때 자식 줄을 같이 지우거나 비우기.
- **OncePerRequestFilter**: Spring에서 요청마다 한 번 도는 필터 만들기.
- **HttpOnly, SameSite 쿠키**: 자바스크립트가 못 읽게, 다른 사이트에서 보낸 요청에 덜 붙게 하는 쿠키 설정.
- **Web Share API / Clipboard API**: `navigator.share`, `navigator.clipboard.writeText`.
- **TanStack Query `setQueryData` / `invalidateQueries`**: 서버 응답으로 캐시를 바로 고치기 vs 낡았다고 표시하고 다시 받기.
- **Soft delete**: 줄을 지우지 않고 지웠다는 표시만 남기는 방법.
