# Feature Specification: 개인 블로그 기본 기능

**Feature Branch**: `001-blog-core`

**Created**: 2026-10-08

**Status**: Draft

**Input**: User description: "깃허브 스펙킷 사용해서 요구사항 작성해줘" (프로젝트 \"blog\", 저장소 home-my-blog/docs). 구체적인 기능 설명이 없어, 한 사람이 운영하는 개인 블로그의 기본 기능을 범위로 잡았다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글 읽기 (Priority: P1)

방문자가 블로그에 들어와 최신 글 목록을 보고, 글 하나를 골라 본문을 끝까지 읽는다.

**Why this priority**: 블로그의 존재 이유는 글을 읽히는 것이다. 이것만 있어도 (글이 미리 들어가 있다면) 블로그로 쓸 수 있다.

**Independent Test**: 공개된 글 몇 개를 준비해 두고, 로그인하지 않은 상태로 목록에서 글을 열어 제목·본문·작성일이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개된 글이 15개 있을 때, **When** 방문자가 첫 화면에 들어오면, **Then** 최신 글부터 10개가 제목, 요약, 공개일과 함께 보이고 다음 페이지로 넘어갈 수 있다.
2. **Given** 공개된 글이 있을 때, **When** 방문자가 글 제목을 누르면, **Then** 글 본문(제목, 서식, 이미지, 코드 블록 포함)과 공개일, 카테고리, 태그가 보인다.
3. **Given** 임시저장 상태인 글이 있을 때, **When** 방문자가 그 글의 주소로 직접 들어오면, **Then** 글이 보이지 않고 "찾을 수 없음" 안내가 나온다.

---

### User Story 2 - 글 쓰고 발행하기 (Priority: P1)

블로그 운영자가 로그인해서 새 글을 쓰고, 임시저장했다가 다듬은 뒤 발행한다. 발행한 글은 나중에 고치거나 내리거나 지울 수 있다.

**Why this priority**: 운영자가 글을 올릴 수 없으면 읽을 글이 없다. 읽기(US1)와 함께 최소 기능이다.

**Independent Test**: 운영자 계정으로 로그인해 글을 작성·임시저장·발행·수정·비공개 전환·삭제하고, 각 단계에서 방문자 화면에 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 운영자가 로그인했을 때, **When** 제목과 본문을 입력하고 임시저장하면, **Then** 글은 운영자 화면에만 보이고 방문자 목록에는 나오지 않는다.
2. **Given** 임시저장된 글이 있을 때, **When** 운영자가 발행하면, **Then** 그 글이 방문자 목록 맨 위에 공개일과 함께 나타난다.
3. **Given** 발행된 글이 있을 때, **When** 운영자가 본문을 고쳐 저장하면, **Then** 방문자에게 고친 내용이 보이고 수정일이 표시된다.
4. **Given** 발행된 글이 있을 때, **When** 운영자가 비공개로 바꾸면, **Then** 방문자 목록과 글 주소에서 더 이상 보이지 않는다.
5. **Given** 글이 있을 때, **When** 운영자가 삭제를 누르고 한 번 더 확인하면, **Then** 글이 삭제되고 목록에서 사라진다.
6. **Given** 로그인하지 않은 사용자가, **When** 글쓰기나 관리 화면에 들어가려 하면, **Then** 로그인 화면으로 안내된다.

---

### User Story 3 - 카테고리·태그·검색으로 글 찾기 (Priority: P2)

방문자가 관심 있는 주제의 글만 모아 보거나, 단어로 글을 찾는다.

**Why this priority**: 글이 쌓일수록 필요해지지만, 글이 적은 초기에는 없어도 블로그가 동작한다.

**Independent Test**: 카테고리와 태그가 붙은 글들을 준비하고, 방문자로 카테고리·태그 목록 화면과 검색 결과가 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 운영자가 글에 카테고리 하나와 태그 여러 개를 붙였을 때, **When** 방문자가 그 카테고리나 태그를 누르면, **Then** 해당하는 공개 글만 최신순으로 보인다.
2. **Given** 공개 글이 있을 때, **When** 방문자가 검색창에 단어를 입력하면, **Then** 제목이나 본문에 그 단어가 들어간 공개 글이 보인다.
3. **Given** 검색 결과가 없을 때, **When** 방문자가 검색하면, **Then** "검색 결과가 없습니다" 안내와 함께 전체 글 목록으로 돌아갈 방법이 보인다.

---

### User Story 4 - 댓글 남기기 (Priority: P3)

방문자가 글에 댓글을 남기고, 운영자는 부적절한 댓글을 지운다.

**Why this priority**: 독자와 소통하는 수단이지만, 블로그의 핵심 가치(글 읽기·쓰기)와는 별개로 나중에 붙일 수 있다.

**Independent Test**: 방문자로 댓글을 작성한 뒤 글 아래에 보이는지 확인하고, 운영자로 그 댓글을 삭제한다.

**Acceptance Scenarios**:

1. **Given** 공개 글이 있을 때, **When** 방문자가 이름과 내용을 입력해 댓글을 남기면, **Then** 글 아래에 작성 시각과 함께 댓글이 보인다.
2. **Given** 댓글이 있을 때, **When** 운영자가 댓글을 삭제하면, **Then** 방문자 화면에서 그 댓글이 사라진다.
3. **Given** 운영자가 어떤 글의 댓글을 닫았을 때, **When** 방문자가 그 글을 보면, **Then** 기존 댓글은 보이지만 새 댓글을 쓸 수 없다.

---

### User Story 5 - 구독하고 공유하기 (Priority: P3)

방문자가 RSS 리더로 새 글을 받아 보고, 글 주소를 메신저나 SNS에 공유했을 때 제목과 요약이 미리보기로 보인다.

**Why this priority**: 독자를 늘리는 데 도움이 되지만 블로그가 동작하는 데는 필요하지 않다.

**Independent Test**: RSS 주소를 리더에 등록해 최신 글이 들어오는지, 글 주소를 공유했을 때 미리보기가 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 글이 있을 때, **When** 방문자가 RSS 주소를 리더에 등록하면, **Then** 최신 공개 글 20개가 제목·요약·주소와 함께 들어온다.
2. **Given** 공개 글이 있을 때, **When** 그 글의 주소를 공유하면, **Then** 미리보기에 글 제목, 요약, 대표 이미지(있으면)가 보인다.

---

### Edge Cases

- 공개 글이 하나도 없을 때 첫 화면에는 "아직 글이 없습니다" 안내가 보인다.
- 존재하지 않거나 지워진 글 주소로 들어오면 "찾을 수 없음" 안내와 함께 첫 화면으로 가는 길이 보인다.
- 운영자가 글을 쓰다가 로그인이 만료되면, 다시 로그인한 뒤 쓰던 내용을 잃지 않는다.
- 제목이 비어 있으면 발행할 수 없고, 무엇이 빠졌는지 안내한다(임시저장은 가능).
- 같은 제목의 글이 여러 개여도 각 글의 주소는 서로 겹치지 않는다.
- 이미지 업로드가 실패하거나 허용 크기를 넘으면, 글은 그대로 두고 실패 이유를 알려 준다.
- 운영자 로그인을 짧은 시간에 여러 번 틀리면 잠시 로그인 시도가 막힌다.
- 같은 내용의 댓글을 짧은 시간에 반복해서 올리면 막는다.
- 카테고리를 지워도 그 카테고리의 글은 지워지지 않고 "미분류"로 옮겨진다.

## Requirements *(mandatory)*

### Functional Requirements

**글 읽기**

- **FR-001**: System MUST 공개 글 목록을 공개일 최신순으로, 한 페이지에 10개씩 보여 준다.
- **FR-002**: System MUST 목록의 각 글에 제목, 요약(운영자가 쓴 요약, 없으면 본문 앞부분), 공개일을 보여 준다.
- **FR-003**: System MUST 글 상세 화면에 제목, 본문, 공개일, 수정일(수정된 경우), 카테고리, 태그를 보여 준다.
- **FR-004**: System MUST 본문의 제목·목록·링크·이미지·인용·코드 블록 서식을 읽기 좋게 표시한다.
- **FR-005**: System MUST 임시저장·비공개·삭제된 글을 방문자에게 목록, 상세, 검색, RSS 어디에서도 보여 주지 않는다.
- **FR-006**: System MUST 각 글에 사람이 읽을 수 있고 바뀌지 않는 고유 주소를 준다.

**글 관리 (운영자)**

- **FR-007**: System MUST 운영자만 로그인해서 글을 쓰고, 고치고, 지울 수 있게 한다.
- **FR-008**: Users(운영자) MUST be able to 제목, 본문, 요약, 카테고리 하나, 태그 여러 개, 대표 이미지를 입력해 글을 만든다.
- **FR-009**: System MUST 글을 임시저장, 공개, 비공개 세 가지 상태로 관리하고 운영자가 상태를 바꿀 수 있게 한다.
- **FR-010**: System MUST 처음 공개한 시각을 공개일로, 마지막으로 고친 시각을 수정일로 기록한다.
- **FR-011**: System MUST 글 삭제 전에 한 번 더 확인을 받는다.
- **FR-012**: Users(운영자) MUST be able to 글 본문에 이미지를 올려 넣는다.
- **FR-013**: System MUST 운영자가 글을 쓰는 중 내용을 자동으로 임시저장해, 창이 닫히거나 로그인이 만료돼도 내용을 잃지 않게 한다.
- **FR-014**: System MUST 운영자 화면에서 모든 상태의 글을 상태별로 걸러 볼 수 있게 한다.

**분류와 검색**

- **FR-015**: Users(운영자) MUST be able to 카테고리를 만들고, 이름을 바꾸고, 지운다.
- **FR-016**: System MUST 카테고리가 지워지면 그 카테고리의 글을 "미분류"로 옮긴다.
- **FR-017**: System MUST 카테고리별, 태그별 공개 글 목록을 보여 준다.
- **FR-018**: System MUST 제목과 본문을 대상으로 공개 글을 검색할 수 있게 한다.

**댓글**

- **FR-019**: Users(방문자) MUST be able to 로그인 없이 이름과 내용을 입력해 공개 글에 댓글을 남긴다.
- **FR-020**: Users(운영자) MUST be able to 댓글을 지우고, 글별로 댓글 쓰기를 닫거나 연다.
- **FR-021**: System MUST 같은 사람이 짧은 시간에 댓글을 반복해서 올리는 것을 막는다.

**구독·공유**

- **FR-022**: System MUST 최신 공개 글 20개를 담은 RSS 피드를 제공한다.
- **FR-023**: System MUST 글 주소를 공유했을 때 제목, 요약, 대표 이미지가 미리보기로 보이도록 정보를 제공한다.

**보안**

- **FR-024**: System MUST 운영자 로그인을 연속으로 5번 틀리면 15분 동안 로그인 시도를 막는다.
- **FR-025**: System MUST 방문자가 쓴 댓글 내용이 다른 방문자 화면에서 코드로 실행되지 않게 한다.

### Key Entities

- **운영자(Author)**: 블로그를 운영하고 글을 쓰는 한 사람. 이름, 로그인 정보, 소개.
- **글(Post)**: 제목, 본문, 요약, 고유 주소, 상태(임시저장/공개/비공개), 공개일, 수정일, 대표 이미지. 카테고리 하나에 속하고 태그 여러 개를 가진다.
- **카테고리(Category)**: 글을 큰 주제로 묶는 단위. 이름, 고유 주소. 글 하나는 카테고리 하나에만 속한다.
- **태그(Tag)**: 글에 자유롭게 붙이는 키워드. 이름. 글과 태그는 여러 개가 서로 연결된다.
- **댓글(Comment)**: 글 하나에 달린 방문자 의견. 작성자 이름, 내용, 작성 시각.
- **이미지(Media)**: 운영자가 올린 이미지 파일. 글 본문이나 대표 이미지로 쓰인다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자가 첫 화면에서 원하는 글 본문을 여는 데 클릭 두 번 이내, 10초 이내면 된다.
- **SC-002**: 운영자가 준비된 원고로 새 글을 작성해 발행하기까지 5분이 넘지 않는다.
- **SC-003**: 일반적인 가정용 인터넷에서 글 상세 화면이 2초 안에 읽을 수 있는 상태로 뜬다.
- **SC-004**: 휴대폰 화면(가로 360px)에서도 가로 스크롤 없이 글을 읽을 수 있다.
- **SC-005**: 임시저장·비공개 글이 방문자에게 노출되는 경우가 0건이다.
- **SC-006**: 공개 글 1,000개가 쌓여도 검색 결과가 2초 안에 나온다.
- **SC-007**: 글 작성 중 창이 닫혀도 마지막 1분 이전까지의 내용은 복구된다.

## Assumptions

- 블로그는 운영자 한 명이 글을 쓰는 개인 블로그다. 여러 명이 글을 쓰는 팀 블로그는 범위 밖이다.
- 방문자는 회원가입 없이 글을 읽고 댓글을 쓴다. 방문자 회원 기능은 범위 밖이다.
- 글 본문은 마크다운 같은 가벼운 서식 문법으로 쓴다고 가정한다.
- 화면 언어는 한국어 하나다. 다국어 지원은 범위 밖이다.
- 방문자 통계, 광고, 뉴스레터 발송, 유료 구독은 이번 범위에 넣지 않는다.
- 댓글은 올리자마자 공개하고, 운영자가 나중에 지우는 방식이다(사전 승인 없음).
- 이미지는 한 장에 10MB까지 올릴 수 있다고 가정한다.
